- **论文对应**：方法节“低秩工程变体”

- **关键代码段**：

  - `src/<pkg>/model.py:737-773` — 构造 $W_{\mathrm{eff}}=W_0+BA$，可在目标函数内部保持行范数，复用全矩阵损失。

- **依赖**：PEFT、bitsandbytes（仅量化路径）、模块 I/O。
- **审计判断**：部署增量秩至多为配置秩，默认秩为 128。启用完整行归一化时，目标函数评估的是归一化后的有效矩阵，而适配器前向通常仍是 $W_0+BA$；源码未在优化后把该归一化投影回适配器，因此存在训练目标与部署映射不一致风险。每个低秩试验开始时 $B=0$，故模型函数回到基座，但 $A$ 继承上一试验；非凸 $A,B$ 优化的参数化起点因此可能依赖试验历史，其定量影响为 `[UNCERTAIN]`。

- **依赖**：Optuna TPE、评估器、模型重置、固定模块 I/O。
- **审计判断**：内层优化改变模块矩阵，外层搜索改变内层超参数。固定 I/O 在模块按序更新和试验间重复使用，因而内层是原模型激活上的局部代理，而不是每次权重更新后重算全网激活的端到端目标。送入 TPE 的第二目标为 $r=f/f_0$（若基线拒答数 $f_0=0$，则退化为原始计数 $f$）。KL 模式的第一目标为

## 数据流图

```text
良性/恶性提示
      ↓
[逐模块前向钩子：提示末位 I/O] ──→ [CPU 固定缓存]
                                      ↓
外层 TPE：层区间、权重、过校正、k ─→ [逐模块局部损失]
                                      ↓
                    [L-BFGS：全矩阵或 LoRA 参数]
                                      ↓
                         [按顺序写回目标模块]
                                      ↓
[生成评估：拒答标记 + 首 token KL/PIQA]
                                      ↓
 [TPE：分段质量分数 + 基线归一化拒答分数]
                                      ↓
 [展示前沿：原始拒答计数 + 原始 KL/负 PIQA 准确率]
```

关键时序是“先一次性捕获 I/O，再运行全部试验”。每个试验内部虽然按层、组件、模块依次写回权重，但不会为后续模块重新捕获已改变模型的上游输入。

## 实现边界与待验证问题

1. **局部代理误差**：I/O 只在原模型上捕获一次，后续模块看到的真实输入可能已被先前权重修改；源码没有校正这一分布漂移。
2. **偏置项缺失**：局部重算使用 $XW^\top$，没有显式偏置；捕获的原输出可能包含模块偏置。[UNCERTAIN] 默认目标架构通常是否无偏置需逐模型核验。
3. **邻域目标非光滑**：`topk` 的邻居身份会切换，负距离项与行归一化使凸性宣称缺少源码支持。
4. **行归一化与 LoRA 部署一致性**：完整归一化只发生在目标闭包内，未见将投影后的有效矩阵回写为等价适配器。
5. **资源规模**：逐模块优化限制单次设备工作集，但保存全部目标模块的双类 I/O 到 CPU；“总内存几乎不增加”不能仅据此成立。
6. **数值与收敛**：源码固定运行 5 次 L-BFGS `step`，没有记录梯度范数、停止原因或失败回退；“通常 2--3 步收敛”属于 PR 陈述而非本审计验证。
7. **评估效度**：拒答字符串与首 token KL 是工程代理，不能单独证明安全性、通用能力或与 SOM 的优劣。
8. **低秩试验历史相关性**：快速重置只清零 $B$，使模型映射回到基座，却保留上一试验的 $A$；参数化起点并非独立初始化，影响为 `[UNCERTAIN]`。
9. **PR 成熟度**：审计时 PR 仍为草稿且未合并；实现与讨论均应视为演化中的研究原型。
